### 8.2.5 断言强度：改了断言，**没改实现**

- **量法**：`tsconfig` 纳入 `tests/` 后，`machine.test.ts` 暴露的一处**真断言缺陷**：

      assert.equal(actual, expected, 1e-12, msg)

  `assert.equal` 只有 **3** 个参数（actual, expected, message）⇒ 这里的 `1e-12` **落到了「消息」位**，
  真正的 `msg` 被丢弃，而且这条断言是**严格相等**（容差根本没生效）。
  **改法**：换成带容差的 `near` 辅助函数。

- 本轮**新写**的测试里有 3 条断言在实测后被证明**写错了**，全部**改断言、不改实现**：

  | 写错的断言 | 实测真相 | 处置 |
  |---|---|---|
  | 「f = x²+y²−1 的等值线端点必须落在单位圆上」 | marching squares 沿格边做**线性**插值，二次场本就不精确（实测最大偏差 0.0282） | 改为「偏差受一阶界 h²/8 约束」+「端点**位级精确**等于该边的插值交点」 |
  | 「rasterPool 每条带都必须是 `ceil(h/(WORKERS×10))` 行」 | 末带是**余数带**（h=97、band=3 ⇒ 末带 1 行） | 改为「等长带 + 末带为余数带，二者正好铺满」 |
  | 「`applyProject("[1,2,3]")` 应报『不是合法 JSON』」 | `"[1,2,3]"` 是**合法 JSON**，只是不是合法工程 | 挪到「顶层不是对象」那条，期望改为『缺少工程版本标记 v:1』 |

- ⚠️ **没做**：既有 5 个测试文件（`cnum` / `geometry` / `linalg` / `machine` / `surface`）的
  **每一条断言的强度没有逐条审计**。本轮只修了 tsconfig 暴露出来的那一处。
  记在 01 的 D 表里，**不当成"没问题"**。

### 8.2.6 同名 `det` 的两套实现：**量清楚，不合并**

- **量法**：`linalg.det`（闭式/LU）与 `machine.det`（高斯消元）各跑 16 000 组随机方阵 + 36 组近奇异 + 边界输入
- 实测结论：

  | 维度 | 结论 |
  |---|---|
  | 方阵（16000 组） | **数学等价**：显著差异 **0 组**；最大绝对差 3e-13。最大相对差 25.6% 出现在 det ≈ 0 的抵消场景 |
  | 非方阵 | **不同**：`linalg` 静默取前 n×n 块（3 行 2 列 ⇒ -3），`machine` 给 **NaN** |
  | 奇异 | 都给 0（`linalg` 经 LU 路径、`machine` 阈值 1e-16） |
  | `inv` 近奇异（36 组） | **2 组分歧** |
  | `solve` 的 b 长度不对 | `machine` 返回 **NaN 数组**（truthy ⇒ `if (!sol)` 判不出），`linalg` 抛错 |
  | `inverse([])` | `linalg` 返回 `[]`，`machine` 返回 `null` |
  | `matMul` | 逐元素完全相同，但 `linalg` 有「跳过零项」优化 ⇒ `0 × NaN` 的边界行为不同 |

- **处置**：**不合并**（`M-13` 未落地）。合并会改变**可观察行为**（错误策略：抛错 vs NaN vs 静默丢列），
  属**产品决定**；本轮**不擅自改**，把分歧逐条列出来交决策人。
- **替代交付**：新增 `tests/linearAlgebraContract.test.ts`（11 条），把**两套实现的契约关系**写成可执行断言 ——
  方阵一致、边界分歧逐条列出、以及「合并的前提是先统一错误策略」这一结论本身。
- 顺带记一条**反直觉的实测**：`linalg.det` 的「3×3 改走 LU」看起来语义等价，
  实测**不等价** —— 因为 `r <= 3` 这个门槛同时决定了**非方阵**的行为（走 `detSmall` 时 `a[2][2]` 是 `undefined` ⇒ NaN）。
  变异验证里它**咬住了**，说明契约测试对这类"看起来等价"的改动有区分力。

### 8.2.7 变异反向验证：**33 条，32 条咬住 + 1 条语义等价**

- **量法**：`/tmp/math_mutation.py`、`/tmp/math_mutation2.py` 与第三轮内联脚本。
  机制：读文件 → 精确字符串替换 → 跑 `npm test` → 记录 → **用内存字节快照还原** → `sha256` 核对。
- 逐条结果（`BITE` = 有测试失败 = 判据咬住了）：

  | 轮 | 条数 | 咬住 | 说明 |
  |---|---|---|---|
  | 一（`contour` / `nn`） | 11 | **11** | C1–C4、N1–N7 |
  | 二（`field` / `cplane` / `view` / `linalg` / `machine` / `rasterPool`） | 14 | **12 → 修判据后 14** | F2、R1 首轮**不咬住**，根因查清并修判据后复验咬住（见下） |
  | 三（`exporters` / `rasterWorker`） | 8 | **7 + 1 语义等价** | E1–E8；E3 是**语义等价变异** |

- **两条「首轮不咬住」的根因（都是判据问题，不是实现问题）**：
  1. **F2「RK4 的 k2 时间点用错」**：收敛阶测试用的场是 `y' = y`，**自治** —— rhs 完全不看 t，
     于是「k2 的时间点写成 `ta+step` 还是 `ta+0.5*step`」对它**没有任何影响**。
     ⇒ **换用非自治场** `y' = t + y`（解析解 `e^t − t − 1`），
     实测误差比 0.1/0.05 = **15.35**、0.05/0.025 = **15.67**（≈2⁴），判据区间取 `[12, 20]`（三阶≈8、二阶≈4 都会被挡下）。
  2. **R1「分带大小算错」**：原判据只断言「带**铺满** `[0,h)`」⇒ 带大小改成一半仍然铺满 ⇒ **判据不敏感**。
     ⇒ 补判据「每条带行数 = `ceil(h/(WORKERS×BANDS_EACH))`（末带为余数带）」。
- **1 条语义等价变异（E3）**：把 worker 的采样区间高度 `y+dy` 改成 `y`，**测不出红** ——
  因为 `domainColor(..., h=1)` 只用第 0 行，区间高度**不参与计算**。**如实归类为语义等价**，不算失败。

- **变异结果同时暴露了一处锚点教训**：`const y = req.yTop + req.dy * (req.start + k);` 在 worker 里出现 **2 次**
  （newton 分支 6 空格缩进、domain 分支 4 空格缩进）⇒ 4 空格锚点是 6 空格行的**子串**，
  「按子串计数」会误判成唯一命中。⇒ **锚点必须带上下文**（本轮据此补跑了 E5/E8 两条）。

## 8.3 关键实测结论（探针产出，全部写进断言）

| 结论 | 量法 | 数值 |
|---|---|---|
| marching squares 的端点是**格边线性插值交点**，不是格心/角点 | 逐端点比对插值公式 | 全部命中，容差 1e-9 |
| 线性插值对二次场的误差是 **O(h²)** | res=8、域[-2,2] 的单位圆 | 最大偏差 **0.0282**，一阶界 h²/8 = **0.03125** |
| 歧义构型（case 5/10）的连通方式符合**标准「格心均值」消解规则** | 构造 `f=(x−0.5)(y−0.5)±0.1` 两例，逐边交点解析可算 | 格心在内 ⇒ 切 b、d；格心在外 ⇒ 切 a、c。**实现完全正确** |
| `nn.ts` 的解析梯度与**中心差分数值梯度**一致 | 中心差分 ε=1e-6，逐参数比对 | 22 个参数，最大绝对误差 **1.5e-10**（tanh/relu/sigmoid 三种激活各测一遍） |
| `softmax` 减去最大值后**大 logit 不溢出** | 偏置拉到 ±1000 | 概率有限、和为 1 |
| `decisionRaster` 按带采样与主线程逐行采样**逐字节相同** | worker 带 vs 主线程逐行 | `domain` 与 `newton` 两条均逐字节相同 |
| `rasterPool` 带长由 `WORKERS×BANDS_EACH` 决定 | 复算模块私有常量 | `WORKERS = max(2, min(4, ⌊cores/2⌋))`（本机 cores=15 ⇒ 4）、`BANDS_EACH = 10` |

> ⚠️ **一条被实测纠正的「疑似缺陷」**：初测时用「等值线两侧场值符号必须相反」判 case 5 的连通，
> 4/4 条线段被判「同号」⇒ 看起来像连错了。
> 查下去发现**判据本身错了**：双曲线弧被线性插值成**弦**之后，弦两侧本来就可能同号
> （弦不是零集）。改用**格心均值消解规则**（marching squares 的标准二义性规则）重算，
> **实现完全正确**，没有缺陷。**记这一条是为了不让下一个人重复踩**。

### 8.6.1 一句话

测试轮解决的是「判据咬不咬得住」，这一轮解决的是「**界面说的是不是真的**」。
最典型的一条：删除参数只从 store 里拿掉滑块，引擎 `globals` 里的变量还在，
于是引用了该名字的曲线依旧照常画出来 —— 用户看到「参数没了、曲线还在」。
同类问题还有 11 处，全部按「对象名 + 后果 + 默认取消」的口径修掉。
